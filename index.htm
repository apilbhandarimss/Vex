VEX — Math Scripting
Language in C

A fully working math calculator language written in C, built by students of Pulchowk Campus. This guide walks through every single line of the source code — what it does, why it exists, and how it all connects.

C Language REPL Recursive Descent Parser BODMAS Enforced ~400 lines
01 — Introduction

What is VEX?

VEX is a tiny programming language that lives entirely inside one C file. You type a math expression like sin(pi/2) + 3^2 and it instantly evaluates it and prints the answer. It is not a library — it is its own interactive environment.

Think of it like a smart scientific calculator where you can also store variables, call functions, and chain calculations together using ans (the last result). Everything you type is evaluated line-by-line, which is called a REPL (Read–Eval–Print Loop).

💡 Big Picture

The entire program is one .c file with 7 clearly labeled sections. Each section handles one job, and they all talk to each other through simple function calls.

02 — Setup

How to Compile & Run

Since VEX uses <math.h>, you need to link the math library with -lm.

# Compile
gcc vex.c -o vex -lm

# Run it
./vex

After running, you'll see the welcome message and the Vex> prompt. Type any math expression and press Enter.

Terminal — vex
Vex Version 0.2.0
Commands: vars | funcs | consts | clear | exit
 
Vex> x = 3 * pi
= 9.42478
Vex> sin(x) + ans
= 9.42478
Vex> exit
Bye!

The REPL — Read, Eval, Print, Loop

REPL stands for Read–Eval–Print Loop. It is the heart of VEX. The program sits in an infinite while(1) loop doing four things forever:

Constants Table

static const ConstEntry CONSTS[] = {
    { "pi",   M_PI             },
    { "e",    M_E              },
    { "tau",  2.0 * M_PI      },

    { NULL,   0                }   /* sentinel */
};
💡 Sentinel Pattern

The last entry { NULL, 0 } marks the end. The parser loops and stops when it sees name == NULL.

Section 2 — Source Code

Functions Table

typedef double (*MathFn)(double);
typedef struct { const char *name; MathFn fn; } FuncEntry;

static const FuncEntry FUNCS[] = {
    { "sin",   sin        },
    { "sqrt",  sqrt       },
    { "fact",  fn_fact    },
    /* ... */
    { NULL,    NULL       }
};
💡 Table-Driven Design

Adding a new function is one line. No parser changes needed.

static double fn_sind(double d)  { return sin(d * M_PI / 180.0); }
static double fn_fact(double n) {
    if (n < 0 || n != floor(n)) return NAN;
    long long r = 1;
    for (long long i = 2; i <= (long long)n; i++) r *= i;
    return (double)r;
}
static double fn_sign(double x)  { return (x > 0) - (x < 0); }

Section 4 — Source Code

Parser Utilities

static void skip_spaces(const char **s) {
    while (**s && isspace((unsigned char)**s)) (*s)++;
}

Advances past whitespace — called constantly so 3 + 4 works like 3+4.

static char *extract_parens(const char **p) {
    int depth = 1;
    while (**p && depth > 0) {
        if      (**p == '(') depth++;
        else if (**p == ')') depth--;
        (*p)++;
    }
    /* ... malloc, copy, return */
}
⚠️ Memory

Always paired with free(inner) after evaluation.

parse_power — right-associativity

static double parse_power(const char **p) {
    double base = parse_atom(p);
    if (**p == '^') {
        (*p)++;
        double exp_val = parse_power(p);   /* recursive = right-assoc */
        return pow(base, exp_val);
    }
    return base;
}
Section 6 — Source Code

Pretty Printer

static void print_result(double r) {
    if (isnan(r))  { puts("= NaN (not a number)"); return; }
    if (isinf(r))  { puts(r > 0 ? "= +Infinity" : "= -Infinity"); return; }
    if (r == (long long)r && fabs(r) < 1e15)
                   printf("= %lld\n", (long long)r);
    else           printf("= %g\n", r);
}
Section 7 — Source Code

The REPL — main()

int main(void) {
    var_set("ans", 0.0);
    while (1) {
        fputs("Vex> ", stdout);
        fflush(stdout);
        if (!fgets(line, INPUT_MAX, stdin)) break;
        /* strip trailing whitespace, check commands */
        double res = eval_expr(line);
        var_set("ans", res);
        print_result(res);
    }
}
How to Extend

Adding Your Own Functions & Constants

/* 1. Write your function */
static double fn_sinc(double x) {
    return (x == 0.0) ? 1.0 : sin(x) / x;
}

/* 2. Add one line to FUNCS[] */
{ "sinc", fn_sinc },

/* 3. Add constants to CONSTS[] */
{ "g", 9.80665 },   /* gravity m/s² */
{ "c", 299792458 },  /* speed of light m/s */
💡 Zero parser changes

Both tables are scanned at runtime — new entries work automatically.

Full Session Examples

Finance: Compound interest

Rajan deposits Rs. 45,000 at 8% p.a. compounded quarterly for 3 years. He then reinvests the full amount plus a Rs. 5,000 bonus at 10% p.a. compounded monthly for 2 more years. VEX chains the two phases using ans, carrying full double precision throughout — no rounding errors from intermediate steps.

Compound interest — two-phase investment
── Phase 1: Himalayan Bank — 8% p.a., quarterly, 3 years ──
Vex> P1 = 45000
= 45000
Vex> r1 = 0.08
= 0.08
Vex> n1 = 4
= 4
Vex> t1 = 3
= 3
Vex> ans = P1*(1 + r1/n1)^(n1*t1)
= 57070.9
→ A = P(1 + r/n)^(nt) — amount after phase 1
Vex> ans = ans + 5000
= 62070.9
→ add Rs. 5,000 employer bonus before reinvesting
── Phase 2: Nepal Investment Bank — 10% p.a., monthly, 2 years ──
Vex> ans = ans*(1 + 0.10/12)^(12*2)
= 75750.7
→ final amount after full 5-year journey
📌 Precision note

VEX carries full IEEE 754 double precision through every step. Manual calculations that round (1.02)^12 to 4 decimal places introduce a ~Rs. 57 drift by the end. Always let VEX hold the full value and only round the final answer.
